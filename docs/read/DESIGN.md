# 栞 — 読書アプリの設計案

タブレットとスマホで使う、個人用の読書アプリ。ミュージック・DESK と同じ作り
（ビルド不要の素の ES モジュール／GitHub Pages／IndexedDB／オフライン）に乗せる前提。

**v0.2 まで実装済み。** 使い方は [README.md](README.md)。
棚・手動進捗・抜き書き・記録に加えて、Markdown / テキスト / EPUB / 青空文庫のビューア、
縦組み、雰囲気5種、紙の調整までが動く。残りは PDF・端末間同期・ConTodo 連携。

- アプリ: `https://aji-daze.github.io/kb-cso/read/`
- 画面案（この文書に対応するモックアップ）: `https://aji-daze.github.io/kb-cso/read/mockup.html`

この文書は設計の理由を残すためのもので、実装の説明は README.md にある。

---

## 0. 結論

### 管理アプリと読書アプリは分けない。1アプリ・2モード

記録が発生するのは「読み終わった瞬間」と「線を引いた瞬間」であって、
あとから別のアプリを開いて入力する習慣は続かない。分けた時点で記録は埋まらなくなる。

### ただし作る順番は管理と Markdown が先

EPUB ビューアも青空文庫の取り込みも、それ自体は安くない。
**いちばん安くて、いちばん早く使えるのは Markdown のビューア**で、これを先に作ると
表示まわり（雰囲気・紙・組み方・ページ送り）を全部作り切れる。
EPUB と青空文庫は、その上に中身の取り出しを足すだけになる。

### 中心機能は抜き書き

読了数や星の数は、自分ひとりで使う分には情報量がほぼゼロ。
あとで参照されるのは引用と、そのとき何を思ったかだけ。ここを一等地に置く。

## 1. 画面

### スマホ

開いた直後に蔵書一覧を出すのは間違い。読む気があってアプリを開いているのだから、
**1冊を全面に出して1タップで本文に入る**のが正しい。棚は下タブに退ける。

| 画面 | 中身 |
| --- | --- |
| **つづき**（起動時） | いま読んでいる1冊を全面に。書影・残り時間・前回止まった位置の直前の一文・「続きから読む」 |
| **棚** | 読んでいる / 積んでいる / 読んだ の3つ。紙・Kindle・EPUB・青空・Markdown を同じ棚に並べる |
| **抜き書き** | 引用と自分の反応。上に「1年前の今日」を1枚だけ |
| **記録** | いつ・何分読んだか。冊数ではなく時間で見る |

読書画面では UI を全部消す。残すのは上端の細線（進捗）と、下の1行だけ。

- **タップ3分割**（左＝戻る / 中央＝UI を出す / 右＝進む）。上下スワイプは誤爆するので使わない
- 残りは「ページ数」ではなく、**実測の読速から出した分**で出す（「この章あと12分」）

### タブレット（横持ち）

縦持ち・1段組にするとスマホの拡大版にしかならない。横持ちの価値は
**本文を読みながら右に書ける**ことにある。

```
┌──────────────────────────┬──────────────┐
│                          │ 抜き書き      │
│   本文（縦組み・1段）      │ ├ 引用       │
│                          │ ├ 自分の反応  │
│                          │ └ タグ       │
│                          │              │
│                          │ この本から    │
│ 第三章        34% あと12分 │ ・…          │
└──────────────────────────┴──────────────┘
        約 70%                   約 30%
```

選択した文はそのまま右に落ち、本文側には薄い印が残る。研究読みはこの形が要る。
縦持ちのときは1段組にして、ノートは下からのシートで出す。

## 2. 本をどこから入れるか

形式ごとに事情がまったく違う。まとめて「対応」とは書けないので、一つずつ分ける。

| 形式 | 入れ方 | アプリ内で完結するか |
| --- | --- | --- |
| 青空文庫 | アプリ内で作者・題名を検索して、そのままダウンロード | **する見込み** |
| Markdown / テキスト | ファイル選択、または共有シートから | する |
| EPUB（DRM フリー） | ファイル選択、または共有シートから | する |
| 洋書（Gutenberg 等） | ブラウザで落としてから、共有シートで栞に渡す | **半分だけ** |
| PDF（自炊） | ファイル選択 | する（タブレットのみ） |
| Kindle | 入れられない。棚に登録して進捗を手で動かすだけ | **しない** |

### 青空文庫

本家 `www.aozora.gr.jp` は CORS ヘッダが無いので、ブラウザから直接は読めない。
**GitHub のミラー（`aozorabunko.github.io`）なら GitHub Pages 配信なので CORS が通る見込み**で、
ここを叩く設計にする。

- 作品一覧の CSV（`list_person_all_extended_utf8`）を初回に一度だけ取り込んで端末内に索引を作る。
  以後の検索はオフラインで済む（約2万作品）
- 本文は**テキスト版ではなく XHTML 版を使う**。ルビが `<ruby>` タグで入っているので、
  縦組みにそのまま流せる。テキスト版は Shift_JIS ＋ `《》` `［＃］` の独自注記で、パーサを1本書くことになる
  （Shift_JIS 自体は `TextDecoder('shift_jis')` でブラウザ標準で読める）
- 著作権の切れた作品なので、端末に保存しておくことに制約がない

> **着手前に1作品 fetch して、実際に通るか確かめること。**
> ここが通らなければこの機能は成立しないので、他のどこよりも先に確かめる。

### 洋書

期待しないほうがいい。`gutenberg.org` は自動取得を制限していて、CORS も期待できない。
Gutendex のような API で**検索と書誌は取れても、本文ファイルの実体は gutenberg.org 側にある**ので別問題になる。

現実的な形:

1. アプリ内で探して、端末のブラウザに渡す
2. 落ちてきたファイルを**共有シートから栞に投げ返す**
   （Web Share Target を `manifest.json` に書く。Android では効く。iOS は非対応なのでファイル選択で拾う）

自前の CORS プロキシを1枚立てれば完結するが、サーバーを持たない原則を壊すので最後の手段。

### Markdown

パーサは自前で足りる（見出し・箇条書き・引用・強調・コード・罫線・リンク）。ライブラリは要らない。

- **ただし縦組みにはしない。** 箇条書きとコードと表が縦に流れると、どこを見ればいいかわからなくなる。
  横組み固定にする
- 抜き書きの書き出しと同じ形式なので、**書き出しと取り込みが対称になる**。
  ThinkOS 側のノートをそのまま読書と同じ画面で読み返せる

## 3. 雰囲気 — 配色ではなく組み方ごと変える

和書と洋書で変えるべきなのは色ではない。行の長さ、字送り、段落の頭、書体の系統が全部違う。
配色だけ切り替えても洋書は洋書に見えない。だから「雰囲気」は**組版のプリセット**として持つ。

| 雰囲気 | 組み方・書体 | 紙 | 効くもの |
| --- | --- | --- | --- |
| 和・縦 | 縦組み／明朝／行間ゆったり／ルビあり | 生成り | 青空文庫の小説、日本語の EPUB |
| 覚え書き | 横組み／ゴシック／行間つめ | 白磁 | Markdown、実用書、自分のノート |
| 洋・古典 | 横組み／欧文セリフ／ハイフネーション／段落一字下げ／頭文字を大きく | 古紙 | 洋書 |
| 研究 | 横組み／ゴシック／小さめ／余白を削る | 白磁 | 通読ではなく参照。ノート併置 |
| 夜 | 直前の組み方を保つ／紙だけ墨に | 墨 | 暗所。紙の目は弱めに落ちる |

雰囲気を選ぶと下の項目（紙・書体・文字・行間・版面）がまとめて動く。動いたあとで個別に触れる。
**プリセットは出発点であって、固定ではない。**

## 4. 紙に寄せる — どこまで効いて、どこから邪魔になるか

画面は発光しているので、紙にはならない。できるのは「発光している感じを減らす」ところまでで、
それ以上やるとコントラストが落ちて読みにくいだけになる。

| 項目 | 中身 | 実装 |
| --- | --- | --- |
| 紙の色 | 白磁／生成り／古紙／セピア／墨。純白は目が疲れる。既定は生成り | token を差し替えるだけ |
| 紙の目 | なし／弱／中／強。ざらつきを1枚重ねる。**ここがいちばん効く** | SVG の `feTurbulence` を data URI で1枚。画像を読み込まないので軽い |
| 綴じ側の陰り | 本を開いたときノドが少し暗くなる、あれ。縦組みなら右、横組みなら左 | グラデーション1枚 |
| 版面 | 広く読む／標準／余白を取る。紙の本は余白が広いが、スマホで真似ると読める量が減る | 余白の変数1つ |
| インクの濃さ | 本文を純黒（`#000`）にしない。紙側とセットで決める | 紙の token に同梱 |

### 上限を抑える

紙の目を強くすると、文字と地のコントラストが縮むだけで読みやすさは上がらない。
**効くのは、効いていると気づかない強さまで。** 「強」でもまだ控えめな位置に上限を置く。

### 夜だけ別扱い

墨の紙にノイズを載せると、画面が真っ黒でなくなるので **OLED の省電力が消える**。
夜の既定は「弱」にして、そこは自覚的に払う。

### 描き直さない

ノイズは背景に固定し、ページ送りでは動かさない。送るたびに再描画すると電池を削る。
めくりアニメを既定オフにしている理由と同じ。

## 5. 入れる機能・入れない機能

「読書体験を楽しむ」で普通に挙がるものの大半は、自分ひとりで使うアプリでは効かない。

| 機能 | 判断 | 理由 |
| --- | --- | --- |
| 縦組み | **入れる** | 日本語の小説では体験差がいちばん大きい。`writing-mode: vertical-rl` で実装できる。ただし横組みとページ送りの計算が別物になる |
| Markdown を読む | **入れる** | 自前パーサで足りる。ThinkOS のノートを読書と同じ画面で読み返せる。ただし横組み固定 |
| 青空文庫の取り込み | **入れる** | アプリ内で検索して落とせる。縦組みとルビを実装する主目的でもある |
| 雰囲気のプリセット | **入れる** | 組版ごと切り替える。和書と洋書で変えるべきは色ではない |
| 紙の目・紙の色 | **入れる** | SVG ノイズ1枚。ただし上限は控えめに抑える |
| 残り時間の実測 | **入れる** | 実測の分/ページから「この章あと◯分」。ページ数より行動を決められる |
| 抜き書きの再会 | **入れる** | 1日1枚、過去の抜き書きを出す。枚数を増やすと見なくなるので1枚固定 |
| 読了時の1問 | **入れる** | 星をつけさせる代わりに「一番残った文は」を抜き書きから1つ選ばせる |
| 読書の記録 | **入れる** | いつ・何分読んだかを DESK の集中セッションと同じ形で残す |
| ページめくりアニメ | **既定オフ** | 紙をめくる演出は最初の3日で邪魔になる。60fps 維持のコストと電池も払う |
| 星評価・点数 | **入れない** | 他人に見せないなら★4と★5の区別に意味がない。付けるのが面倒になって記録自体が止まる |
| 連続日数・バッジ | **入れない** | 途切れた日に開かなくなる。読書は1日空けるのが普通 |
| 効果音・BGM | **入れない** | 音はミュージック側の担当。両方から音を出すと事故る |
| 積読の総数表示 | **入れない** | 数えると買わなくなる方向にしか働かない。今月の出入り（＋2 / −1）だけ出す |

## 6. 正直なところ（先に潰しておく制約）

### Kindle は開けない。回避策も無い

DRM があり、Web から読む手段は提供されていない。Kindle の本にできるのは
「棚に登録して進捗を手で動かす・抜き書きは手打ちかカメラ」まで。

蔵書の内訳を先に数えたほうがいい。Kindle が大半なら、EPUB ビューアの優先度は下がる
（その場合は Markdown ＋ 青空文庫だけで十分に成立する）。

### EPUB は外部ライブラリなしで開ける

EPUB は zip + XHTML なので、ブラウザ標準の `DecompressionStream('deflate-raw')` で展開できる。
epub.js のようなライブラリを抱えずに、ミュージックや DESK と同じ素の ES モジュールのまま実装できる。

### PDF はタブレット専用と割り切る

自炊 PDF の描画には pdf.js が要る（数 MB を同梱する形になる）。
しかもスキャンした固定レイアウトは文字サイズを変えられないので、スマホでは実用に耐えない。

### iPhone / iPad

ホーム画面への追加は Safari 限定。保存領域は長期間開かないと OS に消されうるので、
ミュージックと同じく `persist()` は打っておく。Web Share Target も iOS は非対応なので、
取り込みはファイル選択に落ちる。

### 同期は「進捗と抜き書きだけ」

ミュージック・DESK と同じく端末内のみが原則。ただし読書は
**スマホで読んで、タブレットで続きから**が実際に起きるので、進捗だけは端末をまたぎたくなる。
JSON の書き出し／読み込みでは足りない。Google ドライブの `appDataFolder` に
進捗と抜き書きだけを置く方式（本体のファイルは各端末に持つ）が現実的な落としどころ。

## 7. 作る順番

各段階で単体で使えるようにする。v0.1 だけで止めても損にならない構成。

| 版 | 中身 | これだけで使えるか |
| --- | --- | --- |
| v0.1 | 棚 ＋ 手動の進捗 ＋ 抜き書き ＋ 読書の記録 | **済** |
| v0.2 | Markdown / テキストのビューア（雰囲気・紙の調整・縦横の組み方） | **済** |
| v0.3 | EPUB ビューア | **済**（挿絵は落としている。表紙だけ書影に使う） |
| v0.4 | 縦組み ＋ ルビ ＋ 青空文庫の取り込み、選択からの抜き書き | **済**（青空文庫は配信元の CORS 次第。実機で要確認） |
| v0.5 | 洋書の取り込み（共有シート）、DESK 連携、ドライブ同期、PDF、ConTodo | 共有シートと DESK 連携のみ済。残りは未実装 |

v0.2 で表示を作り切ったので、v0.3 と v0.4 は「中身の取り出し」だけで済んだ。
逆に EPUB から始めていたら、展開と表示を同時に直すことになって詰まっていた。

## 8. 既存アプリとの接続

| 相手 | 内容 |
| --- | --- |
| **ミュージック** | テーマ体系（墨／霧／灰／藍鉄／生成り／白磁 ＋ アクセント ＋ フォント）をそのまま流用する。読書側で足すのは雰囲気・紙・本文設定 |
| **DESK** | 同一オリジンなので localStorage を共有できる。今日の読書分数を集中セッション（`kind: read`）に書く。DESK 側は何も変えずに時間が積算される |
| **ConTodo** | 「◯◯を30分読む」をタスクとして受け取り、読み終わったら消化を返す |
| **ThinkOS** | 抜き書きを Markdown で書き出す。同じ形式で読み込めるので、ノートをそのまま読書画面で読み返せる（双方向） |

## 9. 保存するもの

| ストア | 中身 |
| --- | --- |
| `books` | 書誌（題・著者・形式＝紙/Kindle/EPUB/PDF/Markdown/青空・出どころ・状態・入手日・読了日） |
| `files` | EPUB / PDF / Markdown の実体（Blob。キーは本 ID） |
| `marks` | 進捗（位置・ページ番号・%）と、前回止まった位置 |
| `notes` | 抜き書き（引用・位置・自分の反応・タグ・日時） |
| `sessions` | 読書セッション（本 ID・開始・分数・進んだ量） |
| `aozora` | 青空文庫の作品索引（初回に CSV から作る。検索はここだけで済む） |
| `settings` | テーマ・雰囲気・紙の設定・本文設定・最後に開いていた本 |

ミュージックの `tracks / blobs / art / playlists / settings` と同じ分け方。
実体（`files`）だけ別ストアにしておくと、**本を棚から消さずに実体だけ捨てて容量を空ける**ができる。

## 10. 想定するファイル構成

```
docs/read/
├── index.html      画面の骨組み
├── style.css       ミュージックのテーマ token を流用
├── manifest.json   PWA の設定（Web Share Target もここに書く）
├── sw.js           オフライン用キャッシュ
└── js/
    ├── app.js      画面制御・棚・設定
    ├── db.js       IndexedDB
    ├── zip.js      zip の読み取り（EPUB と青空文庫の索引で共用）
    ├── md.js       Markdown のパーサ（自前・ライブラリなし）
    ├── epub.js     EPUB の展開（DecompressionStream）と章の取り出し
    ├── aozora.js   青空文庫の索引取得・検索・XHTML の取り込み
    ├── pager.js    縦組み・横組みのページ分割とページ送り
    ├── paper.js    雰囲気プリセットと紙の質感
    ├── notes.js    抜き書き・書き出し
    └── stats.js    読速の実測・読書セッション
```

画面を更新したら `sw.js` の `VERSION` を上げる。上げ忘れると古い画面が残る。
