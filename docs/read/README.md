# ぽちゃ文庫（読書アプリ）

読むための画面と、読んだ記録を1つにした個人用の PWA。
ビルド不要の素の ES モジュールで、GitHub Pages にそのまま置いてある。通信なしで動く。

公開先: `https://aji-daze.github.io/kb-cso/read/`

設計の考え方と、入れなかった機能の理由は [DESIGN.md](DESIGN.md) に書いてある。
画面案だけを見たい場合は [mockup.html](mockup.html)。

---

## 1. スマホ・タブレットに入れる

1. Chrome（Android）か Safari（iPhone / iPad）で上の URL を開く
2. Android: メニュー ⋮ →「アプリをインストール」／iOS: 共有 → 「ホーム画面に追加」
3. 追加されたアイコンから起動する（アドレスバーのない全画面で開く）

一度開けば、以後は電波がなくても起動する。
**iOS はホーム画面に追加した状態で使うこと。** Safari のタブのままだと保存の扱いが不安定になる。

## 2. 本を入れる

「＋ 本を入れる」から4つ。

| 入れ方 | 中身 |
| --- | --- |
| **フォルダを開く** | 本の入ったフォルダごと。**OneDrive などの同期フォルダでよい**。一度選ぶと覚える |
| **ファイルを選ぶ** | 1冊ずつ。EPUB（DRM の無いもの）・Markdown・テキスト |
| **Google ドライブから取り込む** | クラウド側を直接辿る（同期フォルダが無い端末向け） |
| **OneDrive から取り込む** | 同上 |
| **青空文庫から探す** | 著作権の切れた作品を、アプリの中で検索して落とす |
| **紙・Kindle の本を登録する** | 本文は開けない。棚に置いて、進みを手で書き込む |
| **見本を入れる** | 使い方を書いた短い文章。読み終えたら消してよい |

Android では**共有シートからも渡せる**（他のアプリで「共有 → 栞」）。iOS は共有シートに対応していないので、
ファイル選択で拾う。

### 青空文庫について

最初に一度だけ作品の索引（数 MB）を落とす。入れたあとの検索は通信なしで動く。

取得元は **GitHub のミラー**（`aozorabunko.github.io`）。本家 `www.aozora.gr.jp` は
ブラウザからの読み取り（CORS）を許可していないので、そちらは使えない。
ミラー側の配信設定が変われば取り込みは止まるが、**他の機能には影響しない**（すでに取り込んだ本は読める）。

本文は XHTML 版を使う。ルビが `<ruby>` タグで入っているので、そのまま縦組みに流せる。

### フォルダを開く（OneDrive はこれが早い）

OneDrive・Google ドライブ・Dropbox は、PC では**同期フォルダとして端末の中にある**。
ならクラウドの API を通す必要はない。そのフォルダをそのまま開けばいい。
**認証もアプリ登録も要らない。**

「本を入れる」→「フォルダを開く」で、例えば `OneDrive\本` を選ぶ。

- **一度選ぶと覚えている。** 次からは選び直さずに中身を確かめられるので、
  OneDrive が同期してきた新しい本がそのまま出てくる
- すでに棚にある本は「✓ 取り込み済み」と出て二重に入らない
- 「まだの ◯件を取り込む」でまとめて入る

#### 使える端末が限られる

フォルダを覚えておけるのは **File System Access API** が使える環境だけ。

| 端末 | |
| --- | --- |
| PC の Chrome / Edge | 覚えられる |
| Android の Chrome | 覚えられる |
| **iPhone / iPad（Safari）** | **使えない。** 一回きりのフォルダ選択に落ちる |
| PC の Firefox / Safari | 同上 |

iPad で読むなら、下のクラウド連携か、OneDrive アプリの共有シートから渡すことになる。

### Google ドライブ / OneDrive（クラウドを直接）

どちらも**読み取り専用**でつなぐ。落とした本は端末に保存されるので、以後はオフラインで読める
（ストリーミングではない）。クラウド側のファイルは一切変更しない。

初回だけ、**自分のアカウントでアプリの登録**が要る。これは避けられない
（他人の鍵を配ると、その鍵で全員のファイルが触れてしまうため）。

| | 要るもの | どこで作るか |
| --- | --- | --- |
| Google ドライブ | OAuth クライアント ID | Google Cloud Console。**ミュージックで作ったものをそのまま使える** |
| OneDrive | アプリケーション (クライアント) ID | Azure ポータル → Entra ID → アプリの登録 |

**OneDrive で詰まりやすいところ**：リダイレクト URI の種別は必ず
**SPA（シングルページアプリケーション）** を選ぶこと。「Web」を選ぶと
ブラウザからトークンを取れずに失敗する。
URI は `https://aji-daze.github.io/kb-cso/read/`（末尾のスラッシュまで一致させる）。

OneDrive は認証のとき一度アプリの外へ出て、戻ってくる。戻ると自動でつながり直す。
つなぎ直し用の記録はこの端末の中にだけ残る（設定 → クラウド → つなぎを切る で消せる）。

### Kindle は開けない

DRM があり、Web から読む手段が提供されていない。回避策も無い。
Kindle の本にできるのは「棚に登録して進みを手で動かす・抜き書きは手打ち」まで。

## 3. 読む

- **左右をタップしてページを送る**。縦組みでは左が先へ進む（右から左へ読むため）
- **中央をタップ**すると、上に目次、下に設定が出る。出ている間はどこを触っても片づけるだけで、ページは送らない
- 本文を**長押しして選ぶ**と、そのまま抜き書きにできる
- 残りは**ページ数ではなく分**で出る。ページを送った間隔からあなたの速さを実測している
  （10ページほど読むと仮の値から実測に切り替わる。飛ばし読みや置きっぱなしのページは捨てている）

## 4. 見た目を変える（読書画面の設定）

中央をタップ → 下のシート。**雰囲気**を選ぶと下の値がまとめて動く。動いたあとで個別に触れる。

### 雰囲気

| | 組み方・書体 | 紙 | 効くもの |
| --- | --- | --- | --- |
| **和・縦** | 縦組み／明朝／行間ゆったり | 生成り | 青空文庫の小説、日本語の EPUB |
| **覚え書き** | 横組み／ゴシック／行間つめ | 白磁 | Markdown、実用書、自分のノート |
| **洋・古典** | 横組み／欧文セリフ／ハイフネーション／頭文字を大きく | 古紙 | 洋書 |
| **研究** | 横組み／小さめ／余白を削る | 白磁 | 通読ではなく参照 |
| **夜** | 組み方はそのまま／紙だけ墨に | 墨 | 暗所 |

選んだ雰囲気は**本ごとに覚える**。小説を縦で読み、ノートを横で読む、が両立する。

### 触れる値

| 項目 | 範囲 | 何が起きるか |
| --- | --- | --- |
| 組み方 | 縦 / 横 | 縦は `writing-mode: vertical-rl`。ページ送りの向きも変わる |
| 書体 | 明朝 / ゴシック / 丸ゴシック / 欧文セリフ | 端末に入っている書体を使う。明朝が無い端末には取り込める（下記） |
| 文字の大きさ | 12–30px | |
| 行間 | 130–280% | |
| 字送り | 0–0.16em | |
| 版面の余白 | 6–72px | 紙の本は余白が広いが、スマホで真似ると読める量が減る |
| **紙の色** | 白磁 / 生成り / 古紙 / セピア / **薄氷** / 霧 / 墨 | 純白は目が疲れる。既定は生成り |
| **紙の目** | 0–100 | ざらつきを1枚重ねる。**ここがいちばん効く** |
| 目の細かさ | 0–100 | ざらつきの粒の大きさ |
| 綴じ側の陰り | 0–100 | 本を開いたときノドが暗くなる、あれ。縦組みなら右、横組みなら左 |
| インクの濃さ | 55–100 | 本文の色を紙に向かって寄せる。純黒にはしない |
| ページ送り | なし / 薄く | 紙をめくる演出は入れない（最初の3日で邪魔になる） |

文字の大きさや行間を変えても、**読んでいた位置はそのまま**。組み直したあと同じ場所に戻る。

### 明朝を取り込む（Android 向け）

**iOS / iPadOS にはヒラギノ明朝が入っているが、Android には明朝が無い。**
Android の標準は Noto Sans CJK（ゴシック）だけなので、書体で「明朝」を選んでも黙ってゴシックで出る。
縦組みで小説を読むのに明朝が出ないのでは、雰囲気「和・縦」の意味が半分なくなる。

設定（右上の歯車）→ **明朝** から、一度だけ落として端末に置ける。

- 書体は **Noto Serif JP**（SIL Open Font License）。Google Fonts から**あなたの端末が直接**落とす。
  このリポジトリには同梱していない
- 全部で約 3.8 MB。ただし **125 個の範囲に分かれていて、必要な字の分だけ読み込む**。
  普通の小説を1冊読むのに実際に展開されるのは十数個で、表示が重くなることはない
- 落としたあとは端末の中（IndexedDB）に残るので、**オフラインでも明朝で読める**
- 端末に明朝がある場合は**そちらが優先される**。設定画面にも「取り込む必要はありません」と出る
- 消したいときは同じ画面から消せる

通信が通らなければ取り込みだけが失敗する。他の機能には影響しない。

#### 紙の目について、正直なところ

- **強くしても読みやすくはならない。** 文字と地の差が縮むだけ。効くのは、効いていると気づかない程度まで。
  「100」でもまだ控えめな位置に上限を置いてある
- **暗い紙にのせると、画面が真っ黒でなくなるので有機 EL の省電力が効かなくなる。**
  「夜」の既定を弱くしてあるのはそのため
- ノイズは背景に固定していて、ページ送りでは描き直さない（電池を削るため）

アプリ側の画面（棚・抜き書き・記録）の配色は、右上の歯車から別に選ぶ。
ミュージックと同じ体系に、アイコンから起こした色を足してある。

- テーマ **しろくま** … 白っぽいグレーの地
- アクセント **水色**
- 紙 **薄氷** … 読書画面用の薄い水色

水色のような明るいアクセントは、明るい地の上では文字として読めない（コントラスト比が 2 を切る）。
そのため**選択中のタブは文字色をアクセントにしていない**。文字は本文色のまま、
アクセントは塗りつぶしたアイコンと上の帯で示している。おかげで
どのテーマとアクセントを組み合わせても選択状態が読める。

テーマ・アクセント・フォントはミュージックと同じ体系。

## 5. 抜き書き

引用と、そのとき書いた自分の反応を対で持つ。**あとで効くのは反応のほう。**

- 上に「1年前の今日」を1枚だけ出す（日替わり。枚数を増やすと見なくなる）
- タグで絞り込める
- **Markdown で書き出せる**。引用・出典・反応・タグの4点セットなので、そのまま文献ノートに積める

## 6. 読了

星はつけない。代わりに「一番残った一文」を抜き書きから1つだけ選ぶ。
他人に見せないなら★4と★5の区別に意味がなく、付けるのが面倒になって記録自体が止まるため。

## 7. 記録

記録の画面には、アプリのシロクマが座っている。**その日に読んだ分数で様子が変わる。**

| 読んだ分数 | 様子 |
| --- | --- |
| 0分 | 寝ている（zzz が浮かぶ） |
| 1〜29分 | 読んでいる |
| 30分以上 | ごきげん（跳ねる・ほおが濃くなる） |

絵は画像ではなく SVG を組み立てている。塗りはテーマの色から取るので、
テーマを変えると本の色も一緒に変わる。息づかい・まばたき・耳の動きは CSS で、
端末が「視差効果を減らす」設定なら止まる。


いつ・何分読んだかを残す。冊数ではなく時間で見る。連続日数やバッジは出さない
（途切れた日に開かなくなるため）。

DESK が同じ `aji-daze.github.io` で配信されていれば、読書の分数は
DESK の集中セッション（`kind: read`）に流れる。DESK 側は何も変えなくてよい。

## 8. 気をつけること

- **保存**: 本の中身はこの端末のブラウザ保存領域に入る。設定 → 「保存を固定する」を有効にしておくと、
  空きが減っても消されにくくなる（推奨）
- ブラウザの「サイトデータを削除」を実行すると**本も抜き書きも全部消える**
- **端末をまたいだ同期はしない。** スマホとタブレットで別々の棚になる。
  抜き書きは Markdown で書き出して移せるが、進捗は移せない
- 元のファイルはバックアップとして残しておくこと（このアプリからは書き出せない）

## 9. アイコン

メガネをかけたシロクマが本を読んでいる絵。

- `icons/character.png` が元絵。アイコンはここから書き出している
- 書き出すのは 512 / 192 / 180（iOS）と maskable 512 の4つ
- maskable だけは中身を 11% 内側に寄せてある。Android が丸く切っても、
  積んだ本とクマの背中が欠けないようにするため
- 地の色は `#a7b7c7`。スプラッシュ（`manifest.json` の `background_color`）も同じ色に合わせた
- アプリ本体の配色（墨・霧・灰…）とは別系統。アイコンは端末のホーム画面に焼き付くので、
  テーマを変えても追随しない

差し替えるときは `character.png` を入れ替えて、同じ4サイズを書き出し、
`sw.js` の `VERSION` を上げる。

### ページ分割のしくみ

DOM には手を入れない。`Range` を作って文字の画面上の位置を測り、
版面の幅で割って「この文字は何ページ目か」を出す。逆に「n ページ目の先頭の文字」は
その関数に対する二分探索で求める。

- 縦組み: `writing-mode: vertical-rl`。内容が右端から左へ伸びるので、`translateX(+n×幅)` で送る
- 横組み: 段組み（`column-width` = 版面の幅、`column-fill: auto`）。`translateX(−n×幅)` で送る

`transform` の分は測る両者に等しく効くので、差を取る計算では補正が要らない。
文字サイズや余白を変えたときは、**変える前の文字位置**を押さえてから組み直して、同じ場所へ戻す。

### 紙の目

SVG の `feTurbulence` を data URI にして1枚敷いているだけ。画像は読み込まない。
明るい紙では `mix-blend-mode: multiply`、暗い紙では `screen`。

### 明朝の取り込み

端末に明朝があるかは、canvas で字幅を測って調べる（`document.fonts.check` はシステム書体に対して当てにならない）。
落とすときは Google Fonts の CSS を読んで `@font-face` を解析し、`unicode-range` と woff2 の URL の対を取り出す。
woff2 は Blob のまま IndexedDB に置き、起動時に `URL.createObjectURL` した URL で `FontFace` を作って
`document.fonts` に足す。**URL で渡すのが肝心**で、こうしておくと
その範囲の字が実際に要るときだけ読み込まれる（ArrayBuffer で渡すと全部展開される）。

画面を直したら `sw.js` の `VERSION` を上げる。上げ忘れると古い画面が残る。
